PERFORMANCE BRICK 8 — NE2000 EVENT-DRIVEN HOST RX

Problem
-------
The UDP tunnel was implemented as a 1-ms GUEST-TIME poll:

    NIC wake source -> every 1 ms guest time
    machine flushes devices
    NE2000 takes _sync
    UdpClient.Available?
    Receive() if anything exists

That is not a DP8390 timing requirement.  It is a host transport implementation
detail, and it forced the whole virtual motherboard to service a fake periodic
deadline even when no Ethernet traffic existed.

Architecture after this brick
------------------------------
HOST SIDE (not guest hardware):
    blocking UDP Receive() thread
        -> exact configured peer filter
        -> bounded ConcurrentQueue of immutable Byte() frames

MACHINE OWNER:
    HardwareBus clock boundary
        -> if queue empty: return immediately
        -> dequeue up to 32 arrived host frames
        -> ReceiveFrameLocked()
        -> DP8390 ring RAM / CURR / ISR / IRQ change normally

The host thread is expressly forbidden from touching:
    packet RAM
    CR/ISR/IMR
    CURR/BNRY
    remote DMA state
    PIC lines

It only transports bytes across the host/card boundary.

Wake semantics
--------------
There is no longer a 1-ms virtual wake deadline.

PicosecondsUntilNextWakeEvent():
    queue empty    -> Long.MaxValue
    frame arrived  -> 1 ps (synchronize at next machine opportunity)

MachineRuntime itself already wakes at most about once per host millisecond when
caught up, and continuously spends slices while in debt.  Therefore an external
host datagram does not require a fake guest-time polling oscillator.

Peer filtering
--------------
The configured UDP tunnel has one peer endpoint.  Received datagrams now must
match BOTH its IPv4 address and UDP port before they enter the host RX queue.
This closes the previous behavior where any sender reaching the bound UDP port
could inject a frame into the guest.

Reconfiguration safety
----------------------
Each tunnel instance has a generation number.  Disconnect/reconfigure:
    1. invalidates the old generation
    2. publishes cable-disconnected
    3. closes the socket (wakes blocking Receive)
    4. joins the old RX worker
    5. clears any stale queued host frames

A frame already returning from the host kernel cannot leak from an old tunnel
into a newly configured one.

Boundedness
-----------
Host RX queue capacity: 256 frames.
Machine drains at most: 32 frames per machine boundary.

This prevents a hostile/fast host sender from growing memory without bound or
making one machine boundary process an unlimited burst.

Preserved guest behavior
------------------------
* Same DP8390 receive filtering (RCR / physical MAC / broadcast / multicast)
* Same receive-ring layout and overwrite behavior
* Same CURR/BNRY handling
* Same PRX/OVW ISR bits and IRQ generation
* Same remote DMA / packet RAM / transmit path
* Same ISA port decode
* Same configured UDP local and peer ports
* Same host PCAP feature

Not changed yet
---------------
Transmit Send() and optional PCAP writes remain host operations reachable from
the machine-side TX path.  They are not periodic polls, so they are intentionally
left for a separate host-I/O extraction if profiling shows a stall with PCAP or
a pathological socket.

File changed
------------
Ne2000Isa.vb

Patch stacking
--------------
Based on Performance Brick 7 Ne2000Isa.vb, therefore preserving the disconnected
fast path work while replacing the connected 1-ms poll entirely.


Disposal publication
--------------------
The host receive worker observes the card's disposed state through Volatile.Read.
Dispose now publishes that Boolean with Volatile.Write, and the machine-side
AdvanceTime fast path uses Volatile.Read as well.  Socket close + generation
invalidation remain the primary worker wake/termination mechanism.
