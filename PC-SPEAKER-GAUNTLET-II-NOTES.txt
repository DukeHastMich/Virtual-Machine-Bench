PC SPEAKER DIGITIZED-AUDIO FIX — Gauntlet II probe

Why this patch exists
---------------------
The supplied DOS Gauntlet II executable is Microsoft EXEPACK-compressed. Static
unpacking shows its PC-speaker ISR very clearly:

  * it installs an IRQ0 handler;
  * it loads AX=00F6h and writes AL then AH to PIT channel 0 (port 40h);
  * 1.193182 MHz / 246 ~= 4850.3 IRQs per second;
  * each IRQ shifts one bit from Sfx.dat, MSB first;
  * the bit is moved into port 61h bit 1;
  * port 61h bit 0 is kept LOW, so this is direct 1-bit speaker drive;
  * Sfx.dat is an offset/length table followed by packed 1-bit sound streams.

The important ISR sequence in the unpacked load module is around 22FC6h:

    mov al,[0735]
    shl byte [0731],1
    rcl al,1
    shl al,1
    out 61h,al

The old PcSpeakerAudio host presenter treated port-61 bit1=0 as
"speaker inactive".  It immediately padded/flushed the current 10-ms waveOut
buffer and reset its filter.  For Gauntlet II that means EVERY ZERO SAMPLE BIT
can terminate a host audio fragment, turning the intended ~4.85-kHz 1-bit stream
into buzz/stutter.

What changed
------------
* A low speaker-data bit is now rendered as the LOW half of the waveform once a
  signal is active.
* Constant-low output is collapsed to the old cheap silent fast path only after
  20 ms, after the DC blocker has effectively settled.
* Normal PIT2 tones still use PIT2.OUT and port 61h bit 1.
* No guest-visible PIT, IRQ, port, CPU, DMA, SB16, wavetable, or storage behavior
  is changed.
* This is deliberately a narrow correctness repair.  The PC-speaker host
  renderer still runs its 48-kHz presentation loop on the machine clock path;
  moving that presentation work to its own host worker can be a later brick if
  profiling shows it is costly.

Expected Gauntlet II result
---------------------------
The DOS release does NOT use Sound Blaster, AdLib, Roland, or the new wavetable
path for its stock audio.  It uses digitized PC-speaker sound.  Some releases had
an optional Tandy SL/TL DAC "enhanced sound disk" (the EXE looks for gtadss.snd);
that file is not present in the supplied gauntlet2.zip.

So Gauntlet II is a PC-speaker torture test, and its previous buzz was evidence
against PcSpeakerAudio rather than SoundBlaster16Isa.
