PC SPEAKER HOST-CLOCK / CONTINUOUS OUTPUT FIX

Observed symptom
----------------
After the Gauntlet II direct-drive repair, its digitized PC-speaker audio became
substantially more recognizable but still had a strong "box fan / helicopter
rotor" modulation.

What this brick changes
-----------------------
1. The 48-kHz PC-speaker presentation loop is removed from PcSpeakerDevice's
   machine-owner AdvanceTime path.

2. Pit8253 now exposes an immutable ChannelOutputSnapshot.  PcSpeakerDevice
   captures channel 2 at the BEGINNING of the coordinated interval (it is still
   registered immediately before the PIT) and posts that snapshot to a dedicated
   host audio worker.

3. The worker reconstructs PIT2.OUT at each 48-kHz sample offset using the same
   mode/counter/phase logic that the previous synchronous GetOutputAtOffset used.
   It never reads or mutates the live PIT.

4. The Gauntlet II direct 1-bit path remains intact:
       node = port61.bit1 AND PIT2.OUT
   A zero data bit is rendered as the LOW level of the waveform, not as an
   instruction to stop/flush the sound stream.

5. WinMM buffer exhaustion no longer drops a 10-ms PC-speaker block.  The
   dedicated host worker is allowed to wait for a completed waveOut buffer.
   The 286 / machine owner is never allowed to wait.

6. The cheap 48-kHz rational phase accumulator stays on the machine timeline so
   the host sample phase remains exact across long silent intervals.  Only the
   expensive per-sample reconstruction/filter/output work moved to the worker.

Files
-----
  PcSpeakerAudio.vb
  HardwareBus.vb

No .vbproj edit is required: both files already exist in the project.

Guest-visible behavior deliberately NOT changed
-----------------------------------------------
  * PIT programming
  * PIT IRQ0 timing
  * port 61h semantics
  * CPU execution
  * DMA
  * SB16 / OPL / MPU / wavetable
  * IDE / ATAPI

Why HardwareBus.vb is included
------------------------------
The live Pit8253 object must not be queried concurrently from the host worker.
The new snapshot is the thread-safe boundary: copy state on the machine owner,
then do host-only reconstruction from the copy.

Build/boot gate
---------------
This environment has no VB/.NET compiler, so the patch was structurally checked
but must be compiled by the project build.  Re-run the SAME Gauntlet II test
first; it is intentionally our torture case.
