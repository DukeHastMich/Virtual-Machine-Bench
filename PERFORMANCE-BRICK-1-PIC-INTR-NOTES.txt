PERFORMANCE BRICK 1 — MASTER 8259A INTR -> 80286 INTR

Purpose
-------
Remove a needless PIC priority calculation from the ordinary CPU instruction
path without changing guest-visible interrupt timing.

Before
------
At every instruction boundary, Processor286 called InterruptAcknowledge whenever
IF was set.  AcknowledgeHardwareInterrupt then called MasterPic.HasPendingInterrupt,
which runs the 8259A pending/priority logic merely to discover that no interrupt
exists.  On a quiet machine this happened after essentially every instruction.

That was also not the electrical AT arrangement: the master 8259A has an INT
output pin which drives the processor INTR input.

After
-----
  slave 8259A INT  ---> master IRQ2       (existing wiring)
  master 8259A INT ---> 80286 INTR        (this brick)

Pic8259.InterruptOutputChanged now drives Processor286.SetInterruptRequestLine().
At an instruction boundary the common no-interrupt path is a single Boolean
test.  Only an asserted INTR pin causes the CPU to perform the existing INTA
callback and ask the PIC for a vector.

AcknowledgeHardwareInterrupt no longer does a redundant HasPendingInterrupt
probe before MasterPic.Acknowledge().  This both avoids a second priority scan
on real interrupts and leaves the PIC's existing spurious IRQ7 behavior in
charge of the narrow INTR-to-INTA disappearance case.

Reset semantics
---------------
The CPU's INTR input latch is intentionally NOT cleared by Processor286.Reset().
INTR is an external motherboard pin.  System reset/power-cycle resets the PIC,
which deasserts its INT output through the normal event wiring.  A processor-only
reset leaves the external PIC line at whatever electrical state the motherboard
is actually driving.

Files changed
-------------
  ProcessorCore.vb
  Declares.vb

Explicitly NOT changed
----------------------
  CPU instruction timing
  PIC priority/mask/EOI rules
  PIT
  DMA
  IDE/ATAPI
  SB16 / OPL / MPU / wavetable
  PC-speaker rendering
  scheduler slice policy
  prefetch queue
  READY timing

Test gate
---------
Build/boot first.  Then compare the same CPU Performance window under roughly
the same DOS workload.  The useful numbers are Effective T-state rate and
Real-time ratio.  Do not change another performance brick until this one has
been measured.
