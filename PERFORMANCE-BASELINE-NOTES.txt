VIRTUAL MACHINE BENCH — RUNTIME DIAGNOSTICS-OFF PERFORMANCE BASELINE
2026-09-05

PURPOSE
-------
This is deliberately NOT a hardware feature change.  It temporarily compiles the
rolling trace/profiler/flight-recorder machinery out of the ordinary runtime so we
can find out how much of the machine's ~27% real-time ceiling is self-inflicted by
observation overhead.

The single master switch is at the top of ProcessorCore.vb:

    Public Module RuntimeDiagnostics
        Public Const Enabled As Boolean = False
    End Module

Set Enabled=True and rebuild to restore the collectors.

WHAT IS DISABLED
----------------
CPU
  * sampled hot-path and detailed datapath Stopwatch profilers
  * instruction/history rings and QB/DPMI/INT/selector/LDT forensic collection
  * routine diagnostic memory-write fan-out
  * fault-reporter byte dumping through the architectural bus
  * 80287 instruction/file diagnostic logging

MOTHERBOARD / BUS / CLOCK
  * READY, HOLD/HLDA, memory and I/O transaction telemetry counters
  * clock-batch flush classification/statistics
  * 8042 raw-wire/history strings and associated read/IRQ counters
  * UART passive diagnostic monitor, register history, LSR polling history,
    and event strings

STORAGE
  * ATA/ATAPI rolling flight recorder and associated phase/stat counters
  * expensive trace-string construction is skipped at the call sites
  * ATA/ATAPI command state, DRQ, IRQ, task-file and data phases are unchanged

VIDEO
  * VGA/DAC trace strings and rolling queues
  * per-write VGA diagnostic PopCount statistics
  * host presentation Stopwatch/counter telemetry
  * scanout/render/publish behavior itself remains active

WAVETABLE
  * recent raw-MIDI and decoded-message histories
  * parser statistics which are not parser state
  * renderer event/frame/underrun statistics
  * especially the per-PCM-frame Interlocked production counter and PCM-peak
    compare/exchange loop
  * render ordering, parser state, outstanding-frame flow control and PCM ring
    pointers are NOT disabled

WHAT REMAINS
------------
  * all guest-visible CPU/chipset/PIT/PIC/DMA/ISA/device behavior
  * machine scheduler and real hardware wake deadlines
  * video presentation, PC-speaker worker, SB16/wavetable audio workers
  * a deliberately small CPU performance display so the before/after ratio can
    still be measured
  * on-demand state-summary functions still exist, but rolling histories will
    naturally show zero/empty while the master switch is False

The performance display's diagnostics-off path copies only a tiny machine snapshot
under the machine gate, then formats/updates WinForms after releasing that gate.
This also removes the audit H23 observer-stalls-machine problem from the baseline.

TEST PLAN
---------
Use the same workloads before making any more emulator correctness changes:

  1. boot DOS and note the real-time percentage
  2. let the same ATAPI CD-ROM driver initialize and compare wall-clock time
  3. run Gauntlet II and listen for whether the helicopter/starvation cadence
     changes as machine speed improves
  4. note idle and busy percentages, not only a single spike

Interpretation:
  * Big jump from ~27% => the diagnostic layer was materially loading the VM.
  * Still near ~27% => stop blaming trace overhead and profile the real execution,
    clock-batching, bus/device, or scheduler hot path next.

BUILD NOTE
----------
No VB/.NET compiler is installed in the patching environment.  The files were
structurally/diff checked, but your normal Visual Studio build is the compile gate.
