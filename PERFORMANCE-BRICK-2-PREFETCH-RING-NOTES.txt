PERFORMANCE BRICK 2 — 80286 SIX-BYTE PREFETCH RING

Purpose
-------
Remove pure host bookkeeping from the instruction-fetch hot path while preserving
the existing modeled six-byte 80286 prefetch queue and its guest-visible memory
fetches.

Before
------
Every FetchByte() consumed queue element zero and then physically shifted the
remaining entries of FOUR arrays one position toward zero:

  _prefetchBytesInBed()
  _prefetchIpsInBed()
  _prefetchCsInBed()
  _prefetchBasesInBed()

That is up to twenty host array assignments for one fetched instruction byte.
Those assignments are not 80286 bus cycles and do not represent any real
hardware behavior.

After
-----
The same six queue entries are stored as a circular FIFO:

  _prefetchHeadInBed  = oldest byte
  _prefetchCountInBed = occupied entries
  write slot          = (head + count) wrapped into 0..5

Consuming a byte now:
  1. reads the current head entry;
  2. advances head by one with a cheap wrap;
  3. decrements count.

No queue payload is copied.

Preserved behavior
------------------
* Queue depth remains exactly six bytes.
* Real guest memory reads used to refill the queue are unchanged.
* CS selector, hidden CS base, and IP metadata are retained per queued byte.
* Queue mismatch still flushes before execution.
* Protected-mode CS validity/limit behavior is unchanged.
* IP still advances exactly once for each consumed byte.
* The 80286 ten-byte maximum instruction check is unchanged.
* Control transfers and LOADALL continue to flush through
  FlushPrefetchQueueInBed().
* Brick 1's master-PIC INTR -> CPU INTR change is included in this ProcessorCore
  baseline and is NOT reverted.

Explicitly NOT changed
----------------------
  instruction timing tables
  READY/wait-state accounting
  CPU memory bus cycles
  PIC/PIT/DMA
  scheduler policy
  REP semantics/timing
  audio
  IDE/ATAPI

Files changed
-------------
  ProcessorCore.vb
