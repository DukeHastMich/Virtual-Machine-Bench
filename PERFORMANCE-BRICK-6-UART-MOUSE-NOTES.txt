PERFORMANCE BRICK 6 — UART / MICROSOFT SERIAL MOUSE HOT PATH

Scope
-----
This is the next iterative Windows-touch optimization.  It changes only host
bookkeeping around the two NS16550A-compatible UARTs and the existing Microsoft
1200-baud serial mouse path.

No serial protocol, baud timing, IRQ semantics, or guest-visible register
behavior is intentionally changed.

1. Idle UART AdvanceTime fast return
------------------------------------
Both COM1 and COM2 are registered clocked devices, so HardwareBus calls
AdvanceTime() at every coordinated clock-batch flush.

Previously an entirely idle UART still entered BeginTransmitIfIdle(),
BeginReceiveIfIdle(), built the generic timing-loop state, and executed one loop
iteration for every flush.

Now it returns immediately when there is provably no time-dependent state:
  * no TX or RX shift register active
  * no queued TX byte or connector RX frame
  * no pending THR->TSR transfer clock
  * no running FIFO receiver timeout

Elapsed time cannot alter an idle 16550 under those conditions.

2. UART line timing cache
-------------------------
DLL/DLM/LCR remain the source of truth.  The UART now recomputes the derived:
  * character duration
  * 16x transmitter-clock interval
  * configured baud
  * data bits / mask
  * parity
  * stop bits

immediately when those guest registers change or the UART resets.

RX/TX completion and FIFO timeout code then reads the cached decoded values
instead of repeating floating-point/division work for every character.

3. UART IRQ pin edge/level-change forwarding
--------------------------------------------
UpdateIrq() previously called Pic8259.SetIrqLine() even when the UART's physical
IRQ output pin had not changed.  SetIrqLine() performs PIC bookkeeping and
interrupt-output recomputation.

The UART now remembers the level it is electrically driving and calls the PIC
only when that level changes.

This is hardware-faithful: a wire continuously held high or low does not create
a new electrical transition because software reread LSR/IIR.

4. Three-byte mouse packet queue
--------------------------------
The Microsoft mouse still emits the exact same three asynchronous characters at
1200 baud, 7N1, through RXD and the normal UART receive shift register.

The mouse no longer allocates a temporary Byte() packet and sends it through an
IEnumerable -> ToArray() path.  QueueReceivedSerialBytes3() enqueues the same
three frames directly and computes their common physical frame duration once.

This is NOT a guest mouse shortcut.

5. Diagnostics-off means diagnostics-off
----------------------------------------
Mouse packet/movement counters and UART dropped-wire-frame counters are used
only by diagnostic text.  Their increments are now behind RuntimeDiagnostics.
Two Form1 raw-mouse diagnostic Interlocked.Increment operations are also compiled
out when diagnostics are disabled.

The actual cross-thread pending X/Y Interlocked operations remain because those
are functional host-to-physical-mouse transport, not diagnostics.

Files changed
-------------
  LegacyIoPorts.vb
  Form1.vb

Patch stacking
--------------
These files have not been changed by Performance Bricks 1-5, so this brick is
independent of:
  * Brick 1 PIC INTR wiring
  * Brick 2 prefetch ring
  * Brick 3 NEAT READY cache
  * Brick 4 S3 batching
  * Brick 5 static port decode

Suggested measurement
---------------------
Test:
  1. DOS prompt with mouse driver loaded.
  2. Windows idle.
  3. Windows while actively moving the captured mouse.

If the gain is negligible, keep only if behavior remains stable and continue to
PIT/RTC/8042/IDE.  The goal is iterative removal of host waste, not per-program
special cases.
