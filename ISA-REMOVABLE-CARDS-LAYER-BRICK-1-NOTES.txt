ISA REMOVABLE CARDS — LAYER BRICK 1
===================================

SCOPE
-----
This brick adds ONLY the infrastructure needed to make ISA cards physically
removable later. It does not add a None option to the UI and it does not move
SB16, NE2000, video, serial, storage, memory, CPU, speaker, or any motherboard
component onto this layer yet.

The running machine should therefore behave exactly as before after this brick.

WHAT CHANGED
------------
1. HardwareBus can now unregister a physical device instance.

   Unregister removes the device from:
     * I/O decode
     * memory/MMIO decode
     * clock advancement
     * wake-source scheduling
     * reset/power-cycle participation
     * memory-decode change events

   It then rebuilds the cold compiled port-decode tables and invalidates the
   memory route cache. No new lookup is added to the hot port/memory path.

2. HardwareBus now rejects registering the exact same physical object twice.
   The registration ledger is cold-path only and is not consulted by guest bus
   cycles.

3. IsaBackplane286 provides physical ISA connector population semantics:
     * Define an 8-bit or 16-bit physical slot.
     * An empty slot is literally empty.
     * Installing a board invokes a factory only at install time, then registers
       that new device on HardwareBus.
     * Removing a board unregisters it and disposes the physical model.
     * Reinstalling creates a fresh physical instance.
     * Installation/removal is rejected while chassis power is marked on.

   This factory rule is important for the eventual None option: a removed SB16
   must not merely be Enabled=False while its audio worker still exists. When a
   slot is empty there is no card object created by the slot at all.

NOT CHANGED
-----------
* No ISA card currently uses IsaBackplane286 yet.
* Declares.vb is untouched.
* Form1.vb is untouched.
* ISA jumper/configuration persistence is untouched.
* System Configuration UI is untouched.
* No guest-visible timing, READY, IRQ, DMA, ROM, or device behavior changes.
* No motherboard component became removable.
* No ISA hot-plug behavior was invented.

BASELINE
--------
HardwareBus.vb is based on Performance Brick 14, preserving the address-aware
VGA/VRAM clock-batching work. Brick 15 only changed DiamondStealthPro928.vb and
is therefore unaffected by this layer.

BUILD VALIDATION
----------------
This environment does not currently contain dotnet/MSBuild/VBC, so I could not
perform a compiler build here. The project XML was parsed and checked locally,
and this brick intentionally has no runtime wiring yet. User-side build remains
the compile gate.

NEXT BRICK (NOT INCLUDED HERE)
------------------------------
Wire only the existing ISA expansion cards through this backplane, preserving
all current default population. After that, None can become a persisted physical
slot state and we can A/B boot with cards genuinely absent.
