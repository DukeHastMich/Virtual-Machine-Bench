REM GUEST MIDI SOFTWARE -> SB16 MPU/MIDI -> WAVEBLASTERCONNECTOR -> WAVEBLASTERDAUGHTERBOARD -> MIDI PARSER/STATE.
REM AFTER DEVICE STATE UPDATE, IMMUTABLE RENDER EVENTS CROSS A NONBLOCKING BOUNDED DEVICE/HOST BOUNDARY INTO WAVETABLEHOST.
REM WAVETABLEHOST RESOLVES THE SHARED ROOT-Banks FILE AND LOADS MELTYSYNTH ON A BACKGROUND THREAD.
REM DEVICE CODE DOES NOT OPEN FILES, ENUMERATE DIRECTORIES, REFERENCE MELTYSYNTH, OR CALL HOST AUDIO APIS.
REM BRICK 6 ADDS A SECOND COMMAND TYPE: RENDER N PCM FRAMES. THE SB16 POSTS IT ONLY FROM ITS COORDINATED AdvanceTime 48 KHZ CLOCK.
REM MIDI EVENTS AND RENDER-FRAME COMMANDS SHARE ONE FIFO SO THEIR ORDER IS DEFINED BY EMULATED MACHINE EXECUTION, NOT DATETIME/STOPWATCH.
REM MELTYSYNTH MIDI PROCESSING AND PCM RENDERING BOTH OCCUR ON THE SAME HOST WORKER THREAD; DO NOT CALL THE SYNTH FROM THE MACHINE/AUDIO THREAD.
REM RENDERED FLOAT PCM CROSSES BACK THROUGH A BOUNDED SPSC RING. THE MACHINE THREAD ONLY DOES NONBLOCKING SAMPLE PULLS.
REM THE CURRENT HOST PIPELINE MAY HAVE A SMALL BUFFERED LATENCY; IF THE WORKER FALLS BEHIND, AUDIO UNDERRUNS/DROPS RATHER THAN STALLING THE 80286.
REM THE SB16 MIXES WAVETABLE PCM THROUGH ITS EXISTING MIDI L/R GAIN PATH AND EXISTING WinMmStereoOut16 OUTPUT. DO NOT CREATE A SECOND AUDIO CLOCK/DEVICE.
REM HOST LOADING/RENDERER FAILURES RESULT IN A SILENT HOST RENDERER STATE + DIAGNOSTICS, NEVER A MACHINE-THREAD EXCEPTION.
REM CONFIGURED BANK POLICY: EXACT REQUEST IF PRESENT; SB16.sf2 AUTOMATIC REQUEST FALLS BACK TO SMALLEST .SF2; OTHER MISSING EXPLICIT REQUESTS DO NOT SUBSTITUTE.
REM CHANGING INSTALLED PROFILE/BANK REMAINS STAGED UNTIL CHASSIS POWER CYCLE.
REM MPU COMMAND-PORT RESET AND MIDI DATA-STREAM SYSTEM RESET ARE DISTINCT.

REM BRICK 6.1 CLOCK MODEL:
REM GUEST HARDWARE TIME REMAINS COORDINATED BY THE MACHINE TIMELINE.
REM HOST AUDIO RENDERING HAS ITS OWN 48 KHZ WORKER CLOCK AND DOES NOT MAKE THE 286 THREAD GENERATE EACH OUTPUT SAMPLE.
REM THE MACHINE OWNER POSTS ELAPSED HOST-FRAME COUNTS; IT DOES NOT MIX OR CALL WAVEOUT PER FRAME.
REM WAVETABLE RENDER REQUESTS ARE POSTED FROM THE MACHINE OWNER TO WAVETABLEHOST IN THE SAME ORDER AS GUEST MIDI, THEN THE HOST AUDIO WORKER CONSUMES THE RESULTING PCM.
REM DO NOT MOVE WAVETABLE RENDER REQUESTS TO A LATER INDEPENDENT QUEUE WITHOUT TIMESTAMPS; THAT WOULD ALLOW FUTURE MIDI TO BE RENDERED INTO EARLIER AUDIO.
