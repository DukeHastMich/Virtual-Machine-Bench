WAVETABLE BRICK 4
=================

Scope:
- Add a device-side MIDI 1.0 byte-stream parser.
- Add renderer-independent 16-channel MIDI state.
- Add bounded decoded-message diagnostics.
- Integrate those pieces into WaveBlasterDaughterboard.

Implemented parser behavior:
- Channel voice messages 80h-EFh.
- Correct 1-byte data length for Program Change / Channel Pressure.
- Running status for channel voice traffic.
- System common F1/F2/F3 lengths and F6/F7 standalone handling.
- Realtime F8-FF can interleave without disturbing partial messages/running status.
- SysEx F0...F7 framing and byte/frame counts, but NO SysEx interpretation yet.
- Malformed/stray guest MIDI is counted/discarded rather than throwing into the VM.

Implemented state:
- 16 channels.
- Note on/off, velocity-zero Note On as Note Off.
- Sustain pedal hold/release bookkeeping.
- Poly pressure and channel pressure.
- Bank select controller storage.
- Program change.
- Volume/expression/pan/modulation and all controller values retained.
- 14-bit pitch bend.
- All Sound Off, Reset All Controllers, All Notes Off.
- MIDI data-stream FFh resets MIDI state.

Still deliberately NOT implemented:
- SoundFont loading.
- Audio rendering.
- PCM mixing.
- Host renderer thread/event queue.
- SysEx interpretation (GM/GS/XG/vendor-specific behavior).
- Any change to SB16 IRQ/DMA/MPU guest-visible port behavior.

The MPU command-port FFh reset remains an MPU-interface reset only.  It is NOT wired
as a physical daughterboard reset without primary documentation establishing that
connection.

Build gate:
This environment does not expose dotnet/MSBuild/vbc, so the project cannot be compiled
here.  VirtualComputer.Modern.vbproj was XML-parsed successfully and contains compile
entries for all three new Brick-4 files.  Build in Visual Studio before starting
Brick 5.
