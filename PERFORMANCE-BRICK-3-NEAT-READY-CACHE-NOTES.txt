PERFORMANCE BRICK 3 — NEAT CPU-LOCAL READY CACHE

Goal
----
Remove repeated host-side policy work from ordinary CPU accesses to motherboard
DRAM and system ROM without changing a single guest-visible wait state.

Board-integrity rule
--------------------
The C&T NEAT chipset remains the authority.

82C212 RB7 currently defines:
  * ROM READY wait states: RB7 bits 1:0
  * RAM READY wait state : RB7 bit 5

NeatCs8221Chipset still stores, decodes, resets, and exposes those bits.  This
brick adds LocalReadyTimingChanged, which publishes the decoded values whenever
RB7 changes or the chipset resets.

NeatMotherboardBridge286 keeps only a hot-path COPY of those two decoded values.
That cache has no independent configuration and cannot override the chipset.

The very next CPU local-memory cycle after an RB7 guest write therefore sees the
new timing.

Fast path scope
---------------
ONLY:
  master = CPU
  ready class = LocalDram OR SystemRom

These two 82C212 values are already expressed directly in CPU READY Tw states,
so no clock-domain conversion is being skipped.

Still uses the full NEAT READY policy
------------------------------------
  * DMA8 memory cycles
  * DMA16 memory cycles
  * refresh/master arbitration
  * motherboard I/O
  * ISA 8-bit cycles
  * ISA 16-bit cycles
  * mapped-device memory
  * open-bus / ISA-hole memory

This is important because DMA adds 82C206 SCLK-derived waits, while ISA timing
depends on BCLK mode, command delay, width, address hold, and board timing
registers.

What host work disappears on ordinary CPU DRAM/ROM cycles
---------------------------------------------------------
Before:
  construct AtReadyCycle286
  -> invoke Func delegate
  -> GetReadyWaitTStates
  -> Select Case ReadyClass
  -> reread RB7-derived property
  -> return same integer

After:
  decoded LocalDram/SystemRom target
  -> read bridge copy of chipset-owned RB7 result
  -> charge SAME integer READY debt

Also moved MasterIndexInBed() behind RuntimeDiagnostics.Enabled so a diagnostics-
off build no longer calculates a diagnostic array index for every READY cycle.

Preserved
---------
  * exact RAM/ROM READY T-state debt
  * CPU timing ledger / B annunciator behavior
  * NEAT register semantics and reset defaults
  * memory decode / shadowing
  * CPU/DMA bus arbitration
  * Brick 1 master-PIC INTR wiring (Declares.vb is based on that version)
  * Brick 2 prefetch ring is untouched (this patch does not contain ProcessorCore)

Files changed
-------------
  HardwareBus.vb
  MotherboardDevices.vb
  Declares.vb

Measurement reference
---------------------
Post-Brick-2 DOS-prompt peak:
  7.678 MT-states/s
  30.7 %
  5,758 T-state slice ceiling

Build/boot and compare at the same DOS prompt before doing another performance
brick.
